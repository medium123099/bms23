# Этапы заказов и доступ по зонам

## Что залить на хостинг
Файлы из архива кладутся в корень сайта с теми же путями (заменить существующие):

- новые: `pipeline.html`, `pipeline_api.php`, `config/pipeline.php`
- обновлённые: `config/schema.php`, `config/admin_ops.php`, `config/max_shop.php`, `max_bot.php`,
  `admin_api.php`, `order.php`, `cabinet.php`, `js/cabinet.js`, `admin.html`

Перед заливкой сделайте копию базы: админка → «Сервис» → «Создать копию сейчас».

## Первый запуск
1. Откройте `admin.html` под администратором (или напишите что-нибудь боту). Таблицы и новые поля создадутся сами.
2. Старые заказы со статусом «Оплачен» станут этапом «Чек» (деньги получены, чек ещё не пробит). Остальные статусы сохранятся.
3. Откройте `pipeline.html` → вкладка «Сотрудники» → «Добавить сотрудника».

## Путь заказа
| Этап | Что делает сотрудник | Что нужно ввести |
|---|---|---|
| Заявка | подтверждает данные (физлицо/юрлицо, реквизиты) | — |
| Счёт | выставляет счёт и отправляет клиенту | номер счёта |
| Оплата | проверяет поступление денег | — |
| Чек | пробивает чек или готовит документ для юрлица | — |
| Отправка | создаёт накладную, отправляет в ПВЗ | номер накладной (ПВЗ по желанию) |

После «Отправки» заказ получает статус «Отправлен», затем «Выполнен». «Отменён» доступен с любого этапа.
Каждый переход записывается в журнал: кто, когда, откуда и куда.

## Права
- **Администратор** (role = admin на сайте, /admin в боте): всё, включая удаление, ручную смену статуса и сотрудников.
- **Сотрудник с зонами** (например, «Счёт» + «Оплата»): видит и двигает только заказы на этих этапах. Может вернуть заказ на шаг назад (с причиной).
  Отменять заказы может сотрудник зоны «Заявка».
- **Вся база** (зона «all»): видит все заказы, включая отправленные и отменённые, двигает любой этап. Не удаляет заказы и не управляет сотрудниками.

## Как подключить сотрудника
1. Сотрудник регистрируется на сайте как обычный пользователь.
2. Администратор добавляет его на `pipeline.html` → «Сотрудники» (имя, телефон аккаунта, зоны).
3. Сотрудник входит на сайт и открывает `/pipeline.html`.
4. Чтобы заказы приходили и в бот MAX: администратор жмёт «Код для бота», сотрудник отправляет боту `/staff 123456`
   (код действует 24 часа). Когда заказ попадает на его этап, бот присылает уведомление с кнопкой «Открыть заказ».

## Бот MAX
Администратор: в меню счётчики по этапам и кнопки каждого этапа. Сотрудник: только свои этапы.
В карточке заказа: кнопка выполнения этапа, «Вернуть назад», физлицо/юрлицо, реквизиты, ПВЗ, комментарий, история, отмена.
Клиенту из бота уходят сообщения о смене этапа (счёт выставлен, оплата получена, заказ отправлен).

## Графы заявки (обновление)

Заказ теперь хранит данные отдельными полями: фамилия, имя, отчество, телефон, email, адрес и пункт СДЭК, агент, комментарий.
Пустые графы (отчество, агент, комментарий) нигде не показываются: ни в уведомлении бота, ни в карточке заказа.
Обязательны: фамилия, имя, телефон, email, адрес СДЭК. Отчество, агент и комментарий можно не заполнять.

Поля для `order.php` (POST): `last_name`, `first_name`, `middle_name`, `email`, `cdek`, `agent`, `phone`, `comment`, `items`, `website` (скрытая ловушка, как раньше).
Пока форма на сайте отправляет только старое поле `name`, заказ принимается по-старому, ничего не ломается.
Колонки в базе (last_name, first_name, middle_name, email, cdek, agent) создаются сами при первом запросе; колонка name расширяется до 190 символов.

Бот MAX при оформлении спрашивает по очереди: фамилия, имя, отчество («-» пропустить), телефон, email, адрес СДЭК, агент («-» пропустить), комментарий («-» пропустить).
На странице «Заказы по этапам» все графы редактируются в карточке заказа.
